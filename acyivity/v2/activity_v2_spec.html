以下 Requirement 2 / 3 内容为系统默认行为，不提供活动层级的开关设置，故不在「新增活动」流程中出现，仅以文字规格呈现。

Requirement 1同期活动入口切换

当后台配置多个进行中的预约活动时，用户进入预约中心后可自由切换不同活动。

  • 支持展示多个进行中的预约活动
  • 默认展示后台配置优先级最高的活动
  • 点击不同入口即可切换对应活动，切换后无需退出页面
  • 每个活动保留独立状态：已预约／未预约／已领取／已结束

v2 补充逻辑（入口模式 a / b）：每个预约活动新增流程第 2 步可选择：

  • 情境 a・加入總入口：活动出现在總入口的统一浮窗切换器内，与其他加入總入口的活动共用一套排序，无需单独设置首页浮窗；總入口本身的图片／开关／排序集中在「活动列表 › 總入口設置」分页管理。
  • 情境 b・獨立入口：活动不进入總入口切换器，保留第一版做法，自行配置专属首页浮窗（PC/H5 图片、开关、排序），用户点击后直接进入该活动页面。

Requirement 2红点提醒

入口新增红点提示，触发条件分为两种情境：

Case A · 存在可领取奖励　优先级 Highest

  • 触发条件：已完成预约 ＋ 已达成领奖条件 ＋ 尚未领取奖励
  • 系统自动判断，不可关闭，非活动层级可配置项

Case B · 存在未查看的新预约活动

  • 触发条件：后台新增活动，用户尚未进入查看过
  • 用户首次进入对应活动后，红点自动消失

两种情境的红点状态均需同步至 Rewards promotion 列表，与活动入口红点保持一致，用户进入后两处同时消失。

Requirement 3站内信提醒

当用户存在可领取但尚未领取的预约活动奖励时，系统自动发送站内信提醒，引导用户前往领取奖励。

  • 触发条件（Case A）：已完成预约 ＋ 已达成领奖条件 ＋ 奖励尚未领取
  • 每个奖励仅发送一次站内信
  • 点击站内信后，跳转至对应预约活动页面
  • 奖励已领取后，不再发送提醒

站内信默认文案模板：

Title：🎁 {活动名称} Reward Ready
Content：Your {奖励} reward is ready to claim! Don't miss out—claim it now.
CTA：Claim Now

可用变量：{活动名称}　{奖励}

與示意圖的對應關係

左侧「後台・活动列表」的「红点-Case A / Case B / 同步 Rewards promotion / 站内信提醒」栏位为状态展示，反映系统依上述规则自动判断的结果，非人工逐一开关；左侧「前台・预约中心」的切换器、红点与站内信面板，均依本规格书的规则渲染。
