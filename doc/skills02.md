## 前言与适用范围

一份完整的需求交付通常包含两部分：**规格文件**（说明每个功能区块的规则、交互与各种情境）与**原型图**（可点选、可预览的界面草稿）。本规范分别定义两者的撰写与制作标准，目标是让美术、前端、PM 等团队成员能够无歧义地理解需求、并能自由接手编辑与扩充。

两部分应彼此对应：规格文件中的每个功能区块都应能在原型图中找到对应界面，原型图中的每个界面也应能回溯到规格文件的对应页签编号（详见第三部分）。

# 第一部分：规格文件规范

## 1. 文档头信息

每份规格文件开头需注明：

1. 文件版本号。
2. 本次「新增、删除、修改」内容摘要。

## 2. 需求目的

简单描述此需求的目的。

## 3. 规则文件内容——前台

### 3.1 前台页面依功能区块以图文方式撰写规则

前台每个功能区块均需配合截图或原型图，并逐项说明以下内容：

- **3.1.1 详细说明交互行为。**
- **3.1.2 文案长度限制。** 例如：一行无法完整呈现时以两行显示，超过即以省略号「…」显示；或一行无法完整呈现即以省略号「…」显示。
- **3.1.3 操作失败后的提示文案及交互行为。**
- **3.1.4 操作成功后的提示文案及交互行为。**
- **3.1.5 需试想各种情境后再撰写规格文件**，避免遗漏分支。

## 4. 规则文件内容——后台

### 4.1 后台页面依功能区块以图文方式撰写规则

后台每个功能区块均需配合截图或原型图，并逐项说明以下内容：

- **4.1.1 详细说明交互行为。**
- **4.1.2 文案长度限制。** 例如：一行无法完整呈现时以两行显示，超过即以省略号「…」显示；或一行无法完整呈现即以省略号「…」显示。
- **4.1.3 操作失败后的提示文案及交互行为。**
- **4.1.4 操作成功后的提示文案及交互行为。**
- **4.1.5 下拉选单的来源及内容。**
- **4.1.6 输入框的限制。** 例如：不可留空、不可输入 0 等。
- **4.1.7 说明开关状态**，包括开启前、开启后分别产生的作用。
- **4.1.8 需试想各种情境后再撰写规格文件**，避免遗漏分支。

## 5. 撰写注意事项

1. 规则说明需明确区分「**新增**」「**异动**」「**不异动**」三类，并另附「**本次未涉及之既有规则**」清单。
2. 所有涉及**判断、状态切换、多选项组合**的规则，需以**表格穷举所有情境组合**，不可只举一两个例子代表，避免遗漏分支。
3. 规则依「**前台／后台**」或不同页面拆开撰写；每个页面规则段落需加注对应**页签编号**（如：对应 3.2.1 页签），方便交叉查阅关联规则。
4. 若规则涉及**条件判断逻辑**，需另附**判断逻辑表或流程图**，不可仅用文字描述。
5. 文案**最小字体不可小于 12px**，且需使用**清晰的字色**（与背景保持足够对比，确保可读性）。

# 第二部分：原型图制作规范

> 本部分已**移除所有针对 Axure 9 / html.to.design 匯入 Figma 的特殊限制**（固定 px 宽度、`white-space: nowrap`、`width: max-content`、禁用 `flex:1`／`1fr`／`min-width:0`、禁用 `rem`/`em` 等）。这些规则原本是为了迁就转档工具而牺牲了响应式、可维护性与可及性。移除后，改以「**干净、标准、可维护、可及**」为第一原则，让 HTML 本身就是高品质、易于团队接手的原型。

## 1. 核心目标

撰写**语义清晰、结构工整、易于维护**的 HTML/CSS 原型，让团队（美术、前端、PM）后续能自由编辑、改字、增删内容与扩充，而不需要事后大量清理代码。品质标准以现代网页最佳实践为准，而非迁就任何单一转档工具。

## 2. 呈现方式

- 使用 **Artifacts**，将所有代码整合在**单一 HTML 档**中。
- **CSS 与 JavaScript 直接内嵌**于 HTML 内，方便单档传递与预览。

## 3. 排版结构（语义化 HTML5）

- 使用标准语义标签：`<header>`、`<nav>`、`<main>`、`<section>`、`<article>`、`<aside>`、`<footer>`。
- 每页使用单一 `<main>`，标题层级 `<h1>`~`<h6>` **循序不跳级**。
- 列表用 `<ul>`/`<ol>`/`<li>`，表格用 `<table>` 搭配 `<thead>`/`<tbody>`/`<th>`。

## 4. 布局与自适应

- 版面布局以 **Flexbox / CSS Grid** 为主。
- **可自由使用**现代响应式属性：`flex: 1`、`min-width: 0`、`1fr`、`%`、`max-width`、`minmax()`、`clamp()` 等——不再有任何禁用清单。
- **文字自然换行**：让内文依容器宽度正常折行；仅在必要处（如长网址、代码）用 `overflow-wrap: anywhere` 或 `word-break` 局部处理。
- 设定合理的**响应式断点**（建议 `640px / 768px / 1024px / 1280px`），确保小屏幕可用。
- `position: absolute` 仅用于**局部叠加**（徽章、图示、下拉浮层），**不用于主要区块排版**。
- `a` / `b` / `code` 等**行内元素保持预设行内显示**，勿加 `display:inline-block`，以免破坏行内文字流。
- 外框容器**不写死固定 px 宽度**，改用 `max-width` 搭配 `%` / `grid`，确保响应式。

## 5. 元件化与命名

- 按钮、输入框、导览标签、卡片等每个元件都要有**清晰、独立的 CSS Class**，结构工整、各自独立包覆。
- 命名采用一致的规则，建议 **BEM**（`block__element--modifier`），例如 `.card`、`.card__title`、`.btn--primary`。
- 用 **CSS 自订属性（Design Token）** 统一管理设计变数：

```css
:root {
  --color-text: #1a1a1a;
  --color-bg: #ffffff;
  --color-primary: #2563eb;
  --space-1: 4px;  --space-2: 8px;  --space-3: 16px;  --space-4: 24px;
  --radius: 8px;
  --font-base: 16px;
}
```

## 6. 字体与单位

- 根字级 `html { font-size: 18px; }`；**内文使用 `rem`/`em`**，方便整体缩放与维持一致比例。
- `line-height` 使用**无单位相对值**（如 `1.5`），以利正确继承。
- 间距（padding / margin）采用**一致的间距刻度**（以 4px 或 8px 为基准），避免随手填数值。

## 7. 视觉与可及性

- 文字与背景维持**高对比度**，至少符合 **WCAG AA**（一般文字 4.5:1、大字 3:1）。
- 维持**工整的网格与舒适留白**，方便后续直接点选与调整。
- 互动元件需具备 `hover` / `focus` / `active` 状态，且 **focus 样式清晰可见**（勿移除 outline）。
- 图片加 `alt`，表单控件搭配 `<label>`，善用适当的 ARIA 属性。

## 8. 代码品质

- 结构分层清楚、命名一致，并用注解分区（如 `/* === Header === */`）。
- CSS 按元件或区块分组，避免重复与魔术数字。
- JavaScript 保持精简、可读，事件绑定集中管理。

# 第三部分：规格文件与原型图的对应关系

为确保两份产物一致，需遵循以下对应原则：

- 规格文件中的**每个功能区块**（前台 3.1、后台 4.1），都应在原型图中有对应的**界面区块或元件**。
- 原型图中的每个界面，应能回溯到规格文件的**对应页签编号**（如「对应 3.2.1 页签」，见第一部分第 5 章第 3 点）。
- 规格文件中以**表格穷举**的情境组合（第一部分第 5 章第 2 点）与**判断逻辑表／流程图**（第一部分第 5 章第 4 点），应能在原型图的各状态（成功、失败、空值、开关开/关等）中被完整呈现。
- 文案长度限制、省略号规则（3.1.2 / 4.1.2）应在原型图中如实体现，以便验证换行与截断表现。
