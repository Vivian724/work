# 一、活动设定列表

> 后台｜消息推送 ＞ 活动消息

## 1.1 页面位置与结构

位置：后台选单「公告管理」＞「消息推送」，新增分页「活动消息」，与现有「app系统推送」「自定义消息」「定时消息」「短信群发」并列。

> **注**：此分页与「自定义消息」分页逻辑不同：自定义消息是操作员手动一次性广播；本功能是系统依规则自动判断触发、仅发送给符合条件且未重复发送过的使用者。

## 1.2 活动设定列表（页面主画面）

显示所有已配置的「消息类型 × 活动」设定（跨消息类型整并显示）。每笔设定绑定一个消息类型与一个活动。**列表上方提供「消息类型」「活动」两个下拉筛选，选择后点「搜索」套用；右侧「新增」按钮开启新增设定弹窗。**

操作栏位（比照后台既有样式，三色实心按钮，横向排列）：

- **确认（绿色）**：将「待确认」状态的设定转为「已确认」（各状态下按钮显示规则详见 1.3 状态机）。
- **编辑（蓝色）**：仅「待确认」状态可点击；点击后开启设定弹窗，栏位同 2.1 新增／编辑设定弹窗，可调整消息标题、消息内容、CTA跳转链接（设定确认后是否仍可编辑，详见 1.3 状态机）。
- **删除（红色）**：点击后先跳出二次确认弹窗（内容「确认删除吗？」，样式详见下方说明）；确认后执行删除，处理原则详见 1.4 资料处理原则。

> **注**：本文件所有「提示」跳窗（含此处删除二次确认、2.2 验证失败阻挡提示）皆统一比照同一套样式：左上角标题「提示」、右上角「✕」可关闭、左侧橘色圆形惊叹号图示、右侧提示文字、按钮靠右对齐。需要操作员二次确认的情境用两个按钮（取消／确定）；纯粹告知、无需选择的情境用单一按钮（我知道了）。

| 栏位 | 型态 | 说明 / 资料来源 |
|---|---|---|
| 消息类型 | 显示，唯读 | 此笔设定所属的消息类型名称，来源为新增当下选择的消息类型 |
| 活动 | 显示，唯读 | 此笔设定绑定的活动名称，来源为新增当下选择的活动 |
| 消息标题 | 显示，唯读 | 此设定目前存储的消息标题 |
| 消息内容 | 显示，唯读 | 此设定目前存储的消息内容；**一行显示不下时以「…」截断，完整内容可于编辑弹窗查看** |
| CTA跳转链接 | 显示，唯读 | 此笔设定的活动专属页面链接；未配置时显示为「－」 |
| 审核状态 | 系统栏位 | 待确认 / 已确认，见 1.3 状态机 |
| 已发送 | 数字，唯读 | 统计此设定已成功发送的通知数 |
| 新增时间 | 显示，唯读 | 取值为操作员点击「确认」当下的时间，非建立设定的时间；「待确认」状态尚未产生此时间，明确显示文字「确认后产生」，不使用「－」（避免与 CTA跳转链接栏位的「－」混淆为同一种意思） |
| 操作人名称 | 显示，唯读 | 建立此笔设定的操作人员帐号 |

## 1.3 状态机（审核流程）

> 列表「操作」栏连动

每笔活动设定新增后，都要经过人工确认，才会真正开始运作：

| 状态 | 说明 | 可执行操作 |
|---|---|---|
| 待确认 | 刚新增、还没被确认的状态；系统不会判断触发条件，也不会发通知 | 确认 / 编辑 / 删除 |
| 已确认 | 操作员按下确认后，系统开始正常判断触发条件、发送通知 | 仅删除（「确认」「编辑」按钮不再显示） |

> **注**：设定一经确认即无法再编辑；如需调整已确认设定的内容，须先删除，再重新新增一笔并重新走一次确认流程。

> **注**：设定转为「已确认」后，系统仅针对「确认时间点之后」才达成触发条件的会员发送通知；确认前即已达成条件、但当时尚未收到通知的会员，**不会**因设定被确认而补发。

## 1.4 资料处理原则

- **删除**：确认后为真删除（二次确认弹窗见 1.2），整笔设定资料由资料库直接移除，不保留历史纪录。**删除设定不会影响「消息列表」中已经发送过的纪录，只有这笔设定本身会消失**（见 1.5 与「消息列表」整合）。
- 新增设定时，消息标题／消息内容会带入消息类型当下的默认文案；送出后此文字即存为这笔设定「自己的一份副本」，与消息类型不再有关联。之后若消息类型的默认文案被修改，所有已存在的设定都维持原本存下来的文字，不会自动跟着变成新文案——即使某笔设定当初完全没被操作员微调过、文字跟消息类型默认值一模一样，也一样不会自动更新。
- 「每个奖励仅发送一次，领取后不再重复」之逻辑由系统自动记录发送状态，不开放后台配置。

## 1.5 与「消息列表」整合

> 既有页面，非新增

「公告管理 ＞ 消息列表」为记录所有已发送消息的既有页面。活动消息一经系统发送，须比照其他消息类型，一并写入此页的发送纪录，供操作员查询与稽核。

- **筛选下拉选单名称为「消息类型」，默认值「所有消息」**，需新增「活动消息」选项。活动消息的发送纪录一样归在「所有消息」底下（选「所有消息」时会一起显示）；操作员另外选择「活动消息」时，则只显示活动消息这个类型的发送纪录。

| 栏位 | 取值来源 |
|---|---|
| 标题 | 此笔发送当下的消息标题 |
| 内容 | 此笔发送当下的消息内容 |
| 消息类型 | **显示该笔发送所属的消息类型名称（如 Reward Ready）** |
| 新增时间 | 实际发送时间 |

# 二、新增／编辑设定弹窗

> 后台｜点击列表「＋新增」或「编辑」开启

## 2.1 新增／编辑设定弹窗

栏位依序标号「① 消息类型」「② 选择活动」，引导操作员依序填写：

- ① 选择消息类型后，画面显示一段灰底提示文字，列出该消息类型固定的触发条件，供操作员确认，此区块不可编辑。
- ② 选择活动（单选）。消息标题 / 消息内容栏位会自动预填该消息类型的默认文案，操作员可微调；栏位旁提供「还原为默认值」，可一键还原并即时更新字数统计，完整规格见下方专章。
- CTA跳转链接为活动层级栏位，非必填（填写规则见下方栏位规格总表，前台呈现详见 3.1）。

> **注**：消息类型本身（名称、触发条件、默认文案）目前仅有一组（如 Reward Ready），暂不建置独立的消息类型管理介面；消息类型以资料库/后端建置方式提供，本页「① 消息类型」下拉选单目前仅会显示此唯一选项。未来若消息类型数量增加，再评估是否需要独立的维护介面。

> **注**：编辑既有设定时，①消息类型、②选择活动两栏位改为唯读，不可变更，仅能编辑消息标题、消息内容、CTA跳转链接。

### （9/17调整）可绑定活动范围

**「② 选择活动」下拉选单仅支援「预约活动」「X-BOMB」两个活动，其余活动一律不显示于选单中。**

两者以外的活动，即使在活动列表中设有「参与角标提醒」，本阶段也不开放绑定；日后若要扩充可绑定的活动，须另行提出需求评估，不可由后台自行新增。

**X-BOMB 另有发送限制（仅刮刮卡奖励会发送），详见 3.1 前台呈现。**

### （9/16调整）弹窗内灰色说明文字的呈现规则

弹窗内共三段灰色说明文字，用途不同、请勿混用；除第②段仅供本文件说明外，其余两段皆需实际做进后台画面：

| 位置 | 是否呈现于后台 | 用途说明 |
|---|---|---|
| ①「① 消息类型」下方灰底字（触发条件） | **需呈现** | 列出该消息类型固定的触发条件，供操作员确认，不可编辑 |
| ②「② 选择活动」下方灰字 | **不需呈现** | 仅为本规格文件的说明用途，开发时不必实作 |
| ③「CTA跳转链接」下方灰字 | **需呈现** | 提醒操作员链接必须加上该活动指定的活动 ID，否则前台点击后无法正确带入活动页 |

③ 的灰字内容为：「活动页面链接，结尾加 ?id={ActivityId}。请原样保留，系统自动带入；留空则不显示按钮。」

### （9/16调整）「还原为默认值」功能规格

此功能本次确认须实作，规格如下：

- **位置**：「消息标题」「消息内容」两个栏位，各自于栏位标题右侧提供一个「还原为默认值」文字链接（蓝色、可点击），两者各自独立。
- **作用范围**：只还原自己所属的那一个栏位——点消息标题旁的只还原标题、点消息内容旁的只还原内容，互不影响。
- **点击后行为**：该栏位内容直接覆盖为「目前所选消息类型的默认文案」（即弹窗开启时预填的那份文字），栏位右下角字数统计同步即时更新；若该栏位当下正显示「缺少变量」的错误提示，该提示一并清除。
- **无二次确认、无成功提示**：点击即还原，不跳二次确认弹窗，也不显示操作成功提示；还原后操作员仍可继续编辑，或重复点击再次还原。
- **不等于送出**：此动作仅改变弹窗内输入框的内容；未按「确认」前取消或关闭弹窗，皆不影响已存储的设定。
- **还原来源**：还原为**该消息类型所配置的文案**，即弹窗开启时预填的那份默认文案，非该笔设定原本存下来的文字（消息类型配置的文案若有调整，还原后即为调整后的文案）。
- **可使用的状态**：仅「待确认」状态的设定可开启编辑弹窗，故新增与编辑两种情境下此功能皆可正常使用；「已确认」设定不可编辑，不会有使用此功能的情境（见 1.3 状态机）。

各情境穷举：

| 情境 | 点击「还原为默认值」后的结果 |
|---|---|
| 栏位文字已被操作员修改过 | 覆盖为消息类型默认文案，字数统计同步更新 |
| 栏位文字与消息类型默认值完全相同 | 内容不变，不显示任何提示，不视为操作失败 |
| 栏位已被清空 | 覆盖为消息类型默认文案，字数统计同步更新 |
| 栏位缺少必留变量，正显示错误提示 | 覆盖为消息类型默认文案，错误提示同时消失（默认文案必定含变量） |
| 已选消息类型、尚未选择活动 | 照常可还原（默认文案属消息类型层级，与所选活动无关） |
| 编辑「待确认」的既有设定 | 照常可用；还原后为消息类型默认文案，非该笔设定原本存下来的文字 |

### 栏位规格总表

| 栏位 | 必填 | 说明 / 资料来源 |
|---|---|---|
| ① 消息类型（选择） | 是 | 下拉选单，来源：现有消息类型清单（触发条件提示区行为详见上方说明） |
| ② 选择活动 | 是 | 下拉选单，单选；**可绑定范围见 2.1**，并需排除「已被任一消息类型占用」的活动（已被占用者不显示于选单） |
| 消息标题 | 是 | 预填消息类型默认值，可依活动微调，最长 50 字；{ActivityName} 取值沿用该活动标题，为必留变量，不可删除（见 2.2 验证规则）；栏位右侧提供「还原为默认值」 |
| 消息内容 | 是 | 预填消息类型默认值，可依活动微调，最长 1000 字；{RewardName} 取值沿用对应奖励名称，为必留变量，不可删除（见 2.2 验证规则）；栏位右侧提供「还原为默认值」 |
| CTA跳转链接 | 否 | 文字（URL），对应此活动专属页面，可留空（前台呈现规则详见 3.1 前台呈现）。**须带上该活动指定的活动 ID；输入框内不得默认任何文案，开启弹窗时保持完全空白，说明一律放在栏位下方灰字** |
| 触发条件 | — | 消息类型固定值，此弹窗不可编辑（下方灰底字是否呈现，详见上方呈现规则） |

## 2.2 验证规则

- **「选择活动」下拉选单仅支援「预约活动」「X-BOMB」（可绑定范围见 2.1）**，且其中已被「任一」消息类型占用者亦需排除（非仅排除同一消息类型内已存在的活动）；两个条件须同时满足才会出现在选单中。
- 消息标题最长 50 字、消息内容最长 1000 字，输入达上限即无法再继续输入（见 2.1 新增／编辑设定弹窗栏位说明）（列表的显示与截断方式见 1.2 栏位规格）。
- {ActivityName} 取值沿用该活动于活动设定中的标题；{RewardName} 取值沿用对应奖励名称；两者为必留变量，微调文案时不可删除。操作员点击「确认」送出时，系统检查两个栏位是否仍包含对应变量：
  - 缺少变量时，无法送出，跳出阻挡提示弹窗（沿用统一提示弹窗样式，见 1.2 活动设定列表说明）：标题「提示」，内容「消息标题缺少 {ActivityName} 变量」／「消息内容缺少 {RewardName} 变量」／两者皆缺时「消息标题缺少 {ActivityName} 变量；消息内容缺少 {RewardName} 变量」，皆统一加上「，请补回后再送出。」，单一按钮「我知道了」，点击后关闭弹窗、回到弹窗内容修改，不会送出。
  - 两个变量皆存在时，才允许实际送出。
- CTA跳转链接为非必填栏位，是否配置会直接影响前台呈现样式，详见 3.1 前台呈现；**若有填写，链接末端须带上该活动指定的活动 ID（栏位下方的常驻提醒文字见 2.1 灰字呈现规则）。**
- **「还原为默认值」不触发任何验证、也不等于送出**，送出时仍须通过上述检查（完整规格见 2.1）。
- 消息标题、消息内容、所属活动、消息类型皆为必填，未填写不可送出；CTA跳转链接为非必填栏位，可留空送出。

# 三、前台呈现

> 会员端｜消息中心 ＞ 收件箱

## 3.1 前台呈现（消息中心）

活动消息发送后，比照既有站内信规则显示于会员端「消息中心 ＞ 收件箱」，最新一笔以「本次新增」标示。

### 触发规则

- 触发条件依所选消息类型固定规则判断（如 Reward Ready：已达成领奖条件＋奖励尚未领取），详见 2.1 新增／编辑设定弹窗。
- 每个奖励仅发送一次，领取后不再重复（见 1.4 资料处理原则）。
- 站内信本身没有独立的开关可单独关闭；若要停止发送，须至 1.2 活动设定列表将对应设定删除，设定一旦删除即不再触发发送。

### （9/17调整）X-BOMB 活动发送规则

- X-BOMB 活动中，仅「刮刮卡」奖励会发送活动消息，其他奖励不发送。

### 呈现形式

活动消息以两种形式呈现给会员，两者皆归类于消息中心「收件箱」、与既有站内信并列：

- **收件箱列表／详情页**：常态呈现，App／H5／PC 皆有，会员可在消息中心随时查看；**App／H5 无跳出式弹窗，以返回键返回列表，非「✕」关闭**。
- **跳出式弹窗**：比照既有站内信弹窗机制，于会员进入前台时主动跳出提醒；**仅 PC 版才有此弹窗**，App／H5 版不会跳出弹窗。

### CTA 按钮呈现规则

- **PC 弹窗、有配置 CTA跳转链接**：共两个可互动元素——「Claim Now」按钮（点击跳转至对应活动页）＋右上角「✕」关闭。
- **PC 弹窗、未配置 CTA跳转链接**：比照一般站内信弹窗样式，仅一个「Confirm」按钮，点击仅关闭弹窗、不跳转；不显示「✕」。
- 收件箱详情页比照上述同一套「有／无 CTA」逻辑：有配置链接时显示「Claim Now」按钮并可跳转；未配置时按钮不显示。

### 默认文案

|---|---|
| Title | {ActivityName} Reward Ready |
| Content | Your {RewardName} reward is ready to claim! Don't miss out—claim it now. |
| CTA | Claim Now → 跳转至对应活动页（未配置链接时不显示） |
