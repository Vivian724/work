#### 需求目的

- **做越多拿越多**：任务组每完成一个领一份，完成到指定数量再送额外奖励。
- **奖励更多样**：新增免费旋转、免费投注、优惠券、golden draw券。
- **控制成本**：每项奖励可设人数名额。
- **精准投放**：按 VIP、标签、累计充值／投注指定谁能参加。

| 名词 | 意思 |
|---|---|
| 基础任务 | 一个条件＋一份奖励；既有的任务都是基础任务。 |
| 任务组 | 多个子任务包成一个任务，完成一个领一个。 |
| 子任务 | 任务组里的一个小任务，各有条件、奖励、跳转。 |
| 额外奖励 | 任务组里完成到指定数量（任意 n 个）再送的奖励，最多 3 档。 |

## 2 后台：怎么配

### 2.1 后台 · 基本信息

位置：任务设置 › 点「＋ 新增任务」或「编辑」打开弹窗。表单分 5 区：基本信息、任务内容、参与对象、时间与发放、其他。

#### 规则

- **任务类别 ***：基础任务（预设）／任务组。选任务组，任务内容区改成子任务＋额外奖励（2.3）：任务条件、任务奖励、跳转地址、游戏页展示收起，改显示子任务（预设 2 个）、额外奖励（预设 1 档）；名额上限两种都有。
- **编辑时**：任务类别反灰不可改。
- **游戏页展示**（**改名**：原「任务标签」，选项、逻辑照既有）：选项「无、体育、电子、真人、小游戏、其他」，决定任务卡出现在前台哪个游戏分类页的「Task」区块。**任务组不适用**：选任务组时这一栏收起。
- **币种、任务名称**：照既有。任务名称在前台只显示一行，超出以「…」截断。

### 2.2 后台 · 任务内容（基础任务）

基础任务＝一个条件＋一个跳转地址＋一份奖励。

#### 任务条件 *

先选大类，再选条件：

| 大类 | 条件 | 目标值 |
|---|---|---|
| 信息完善 | 填写真实姓名、填写生日、填写手机号码、填写邮箱、KYC认证、Maya绑定、Glife绑定 | 不用填 |
| 资金 | 充值、投注、Maya充值、Maya提款、Glife充值、Glife提款 | 充值类：金额（0＝不限）<br>投注：金额＋限制游戏（不勾＝全部游戏） |
| 其他 | 2025新版访问、关注Facebook、体验平台PWA、圣诞倒计时专属任务、Brand Daily Passcode | 不用填 |

- 不含「首次充值」「首次充值(阶级)」。
- **Maya绑定、Maya充值、Maya提款、Glife绑定、Glife充值、Glife提款**：保留选项，目前没在用，**QA 不用验测**；原型「新手成长计划」里的 Maya／Glife 子任务只是为了示范 10 个子任务上限。
- 条件会限制能选的任务时间（2.6）。
- **连动**：先选大类 → 条件下拉换成该类的选项、预设第一个；充值类条件 → 出现「充值金额」框；「投注」→ 出现「限制游戏配置」钮＋有效投注金额；其他条件没有目标值栏位。子任务同。

#### 任务奖励 *

| 奖励类型 | 要填什么 |
|---|---|
| 彩金 | 奖励值＋彩金流水倍数 |
| 积分 | 奖励值 |
| 免费旋转／免费投注／优惠券 | 下拉选一张券（沿用券管理后台已建立的券）＋价值（预设 0）；每次发 1 张 |
| golden draw券 | 张数 |

- **只能填整数（新增）**：彩金、积分的奖励值，以及券类的「价值」，一律只能填**整数**；小数点、非数字都打不进去。基础任务、子任务、额外奖励都一样。
- **6 位数上限（新增，只限额外奖励）**：额外奖励的上述栏位**最多 6 位数**（最大 999,999），第 7 位打不进去。原因：前台宝箱下方最长只放得下 6 位数＋单位。基础任务、子任务**不限位数**。
- **价值（新增）**：券类才有，填这张券值多少 ₱（整数），**预设 0**。
  - 只给前台显示用：任务卡奖励标签、额外奖励宝箱、奖励找回清单、领取成功弹窗、提示弹窗都显示「₱价值」（对照见 3.2）。
  - 不影响发放：实际发给会员的是下拉选的那张券。
  - 没改就是 0，前台显示 ₱0。例：选「ON色碟」、价值填 20 → 前台显示 ₱20。
- **券名称**：就是券管理后台建券时取的名称（如 ON色碟），任务后台不另填。前台只有领取成功弹窗显示（3.6），**原样显示、不翻译**，英文站也一样。
- 子任务、额外奖励的奖励也是这 6 种；券类一样要填价值；都只能填整数，6 位数上限只有额外奖励适用。

#### 跳转地址 *

- 下拉选单，照既有清单。前台「去完成／去充值／去投注」点了跳到这里。

### 2.3 后台 · 任务内容（任务组）

一个任务组＝多个子任务，完成一个领一个；完成到指定数量，再送额外奖励。前台显示：任务组卡（3.3）、额外奖励宝箱（3.4）。

#### 子任务

- **数量**：预设 2 个，最少 1 个，最多 10 个。满 10 个「＋ 添加子任务」反灰；只剩 1 个时「删除」反灰。新加的子任务预设「资金 · 充值」＋积分；跟其他子任务没有共同任务时间时，自动换成可以放一起的条件（2.6）。
- **内容**：每个子任务一个**名称**＋一个条件＋一份奖励＋一个跳转；条件、奖励、跳转规则同 2.2。
- **子任务名称 ***：子任务卡片里的「名称」，规则**同「任务名称」**（必填、国际化、字数）；前台子任务行显示这个名称，1 行，超出「…」。任务组名称＝上方「任务名称」。
- **ID**：母ID-序号，显示在每个子任务标题旁。<br>新增任务时：删掉一个子任务，后面的序号往前补。<br>编辑已建立的任务组时：序号固定不动，删掉的号码空着不再用，新加的接在最大号后面。例：有 1030-1、-2、-3，删掉 -2 再新增一个 → 1030-1、-3、-4。
- **任务时间**：整组共用，在 2.6 设定。

#### 额外奖励

- **写法**：「任意完成 n 个」＋奖励。不限哪几个、不分先后。
- **档数**：**必填，最少 1 档**，最多 3 档，且不超过子任务数；每档的 n 不能一样（例：不能有两档都是「任意完成 2 个」）。
- **按钮与下拉**：「任意完成 __ 个」下拉＝1～子任务数，别档已选的数字反灰；档数到上限（3 或子任务数，取小的）「＋ 添加额外奖励」反灰；只剩 1 档时「删除」反灰。新增表单预设 1 档空白。
- **发放**：每档发 1 次，不受名额限制。
- **审核**：额外奖励**不用审核**。完成数一达到 n，奖励就成立。任务组选「人工审核」时，只审子任务（子任务审核通过才算完成），额外奖励本身不再审。
- **领取**：跟子任务一样，照后台「奖励发放方式」（2.6）：选自动发放＝直接入帐；选用户手动领取＝会员在前台点宝箱领（宝箱样子见 3.4）。
- **计算**：完成数按当期算，跟着任务时间重置。

#### 例子

子任务：① 充值 ₱100 → 积分 100 ② 投注 ₱1,000 → 积分 150 ③ 投注 ₱200 → 积分 200<br>额外奖励：任意完成 1 个 → 积分 50 2 个 → 彩金 100 3 个 → 积分 500

| 会员做了 | 完成数 | 拿到 |
|---|---|---|
| ② 投注 ₱1,000 | 1 / 3 | 积分 150 ＋ 积分 50 |
| ① 充值 ₱100 | 2 / 3 | 积分 100 ＋ 彩金 100 |
| ③ 投注 ₱200 | 3 / 3 | 积分 200 ＋ 积分 500 |

#### 补充

- 删子任务后，某档额外奖励要求的数量比剩下的子任务还多：该档「任意完成 __ 个」的数字会自动清空，要运营重新选或删掉那一档。例：原本 3 个子任务、有一档「任意完成 3 个」，删到剩 2 个，这档就做不到了，所以清空。
- 删子任务后，额外奖励的档数比子任务还多（例：3 档、删到剩 2 个子任务）：多出来的那档选不到数字，要删掉那一档才能保存。

### 2.4 后台 · 名额上限

名额上限＝一项奖励最多让几个人领到，先领先得。在「任务内容」区最下方设定。

#### 规则

- **怎么填**：正整数；留空或 0＝不限。任务时间选「永久」时反灰、清空；切回其他任务时间，带回原本填的数字。填大于 0 时，奖励领取时限立即反灰、清空（2.6）。
- **永久任务不能设名额**：信息完善，以及「其他」里的 2025新版访问、关注Facebook、体验平台PWA，只能选永久（2.6），所以一定不能设名额。
- **基础任务**：这个任务的奖励最多 N 人领到。
- **任务组**：每个子任务**各自计算**，**共用同一个上限数字**。<br>例：填 1000 → 子任务1 最多 1000 人、子任务2 最多 1000 人……互不影响。额外奖励不受名额限制：子任务额满，宝箱照样算这个子任务已完成。
- **怎么算人数**：**实际领取才算 1 人**——任务中心点「领取」、自动发放都算。**已达到领取资格、但还没实际领取的，都不算进名额**。同一人一期只算一次；每一期重新计算。<br>例：填 1000 → 这项奖励**每期**最多 1000 人领到。
- **满了**：还没领到的人都不能再领（含已完成待领取的），后台记录「额满」，前台按钮「额满」（3.5）。

#### 补充

- 人工审核的任务：审核通过后领到奖励才算 1 人；提交待审核时不算。
- 有设名额（大于 0）就不能设「奖励领取时限」（反灰、清空）：这项任务不进奖励找回，当期没领就领不到（2.6、3.8）。

### 2.5 后台 · 参与对象

决定谁能参加。前台：**VIP、标签不符合＝看不到**；参与要求没达成＝看得到、按钮引导去完成。各情况见 3.7。

#### 规则

- **VIP 等级**：多选 VIP0～VIP4；都不勾＝不限。
- **用户标签**：多选，分一级、二级标签；都不勾＝不限。勾多个＝**全部都要有**（AND）。例：勾 TH、ML，会员要同时有 TH 和 ML 才能参加。
- **VIP 与标签**：要同时符合（VIP 在勾选范围内，且标签全部都有）。
- **任务参与要求**：选填，勾了才生效：完成KYC／完成KYC部分认证、累计充值大于等于、累计有效投注大于等于（各填一个金额）。**整块照既有，本期不改。**

#### 补充

- 累计充值／累计有效投注没勾：输入框反灰、清空；勾了才能填。

### 2.6 后台 · 时间与发放

设定任务什么时候有效、怎么审核、奖励怎么发。

#### 交互一览（改了 A，B 跟着变）

| 操作 | 跟着变 |
|---|---|
| 改任务条件 | 不支持的任务时间反灰；目前选的变成不支持 → 自动改选第一个可选的（下表） |
| 任务时间选「永久」 | 名额上限反灰、清空；切回其他任务时间，带回原本的数字（2.4） |
| 任务时间选「限时」／「周限时」 | 下方出现起讫日期时间／星期区间 |
| 发放方式＋任务时间 | 「用户手动领取」＋每日／限时才出现「奖励领取时限」；其他组合不显示 |
| 名额上限填大于 0 | 奖励领取时限反灰、清空；改回留空或 0 → 恢复可填，要重新填 |
| 审核方式 | 表单内没有连动；只影响完成判定（人工＝审核通过才算完成） |

#### 规则

- **任务时间 ***：永久／每日／每周／限时（起讫日期时间）／周限时（星期几 至 星期几）。周期照既有。前台：决定在哪个页签（3.1）、有没有倒数（3.2）。
- **条件搭配**：条件不支持的任务时间反灰（下表）；任务组只能选所有子任务都支持的任务时间。
- **审核方式 ***：自动审核／人工审核；人工以「审核通过」为完成。任务组选人工审核时，只审子任务；额外奖励不用审核。前台：人工审核点「领取」后显示「处理中」（3.5）。
- **奖励发放方式 ***：自动发放／用户手动领取；子任务、额外奖励照同一设定。前台：手动领取＝有「领取」钮、宝箱可点、领了跳领取成功弹窗；自动发放＝直接入帐、宝箱直接打勾、不跳领取成功弹窗，由提示弹窗通知（3.4、3.6、3.9）。
- **奖励领取时限**：什么情况能填、有什么限制，见下方「奖励领取时限」。
- **排序**：任务组和基础任务**一起排**，数字越小越前面（照既有）。前台卡片顺序见 3.1。

| 条件 | 永久 | 每日 | 每周 | 限时 | 周限时 |
|---|---|---|---|---|---|
| 信息完善（全部）；其他：2025新版访问、关注Facebook、体验平台PWA | ✓ | — | — | — | — |
| 资金（充值、投注、Maya／Glife 充提） | — | ✓ | ✓ | ✓ | ✓ |
| 其他：圣诞倒计时专属任务、Brand Daily Passcode | — | — | — | ✓ | — |

#### 补充

- 限时：早于开始的结束日期反灰不能选；先选了结束、再把开始改到结束之后 → 结束清空，要重选。周限时：两个星期下拉，照既有。
- 改了条件后，原本选的任务时间变成不支持：自动改选第一个可以选的任务时间。
- 任务组：子任务下拉里，跟其他子任务没有共同任务时间的条件反灰（例：已有「投注」，不能选「关注Facebook」）；新加的子任务自动带可以放一起的条件。
- 适用端口：在本区，照既有。排序、是否显示任务简介、任务简介、任务状态：在表单最下方「其他」区，照既有；任务简介的前台显示见 3.10。

#### 奖励领取时限

当期没领的奖励，重置／结束后 N 天内可在「奖励找回」（3.8）补领。照既有，本期只多一条：**有设名额就不能填**。

| 情况 | 奖励领取时限 |
|---|---|
| 用户手动领取＋每日／限时＋没设名额 | 可以填 |
| 用户手动领取＋每日／限时＋有设名额 | **反灰、清空**（新增） |
| 其他（自动发放；永久、每周、周限时） | 不显示 |

- 单位天，**预设 1**；每日＝重置后起算，限时＝结束后起算。
- 超过 N 天没领＝放弃，不能再领；完成记录的状态照既有。
- 额外奖励不进奖励找回（3.4）；任务组有设名额＝整组不进（名额是整组一起设的）。

### 2.7 后台 · 任务设置列表

位置：运营后台 › 任务中心管理 › 任务设置。列表一行一个任务。

#### 规则

- **栏位**：照既有（任务ID、任务类别、任务名称、适用等级/层级、适用端口、任务时间、审核方式、排序、任务状态、操作），**只新增「名额」一栏**，放在适用等级/层级后面。条件、奖励等其他设定点「编辑」查看。
- **任务组（母行＋明细行）**：第一行是任务组本身，显示整组的设定和操作；下面缩排列子任务（灰字），一行一个，只显示任务ID、任务类别、任务名称、名额，其他栏位留空。额外奖励不列出。
- **任务ID**：子任务＝「母ID-序号」，例：1030-1。
- **任务类别**：既有栏位，多「任务组」一个值；子任务行显示「子任务」。
- **任务名称**：子任务行＝子任务名称（前面不加符号），后面也有「＋」可设国际化（同任务名称）。
- **适用等级/层级**：只显示有勾的 VIP、标签；都没设（VIP 全选或没勾、标签没勾）＝「—」；只设其中一种，就只显示那一种。
- **名额（新增栏位）**：有设上限＝「已领取 / 上限」（例：512 / 1,000），已领取＝当期人数，每期重算（同 2.4）；满了照样显示（200 / 200），不另加样式。任务组母行「—」，子任务行各自显示「已领取 / 上限」（每个子任务各自算，2.4）。没设或永久＝「—」。
- **任务时间**：限时显示起讫时间；周限时显示「星期一 至 星期五」这类区间。

#### 补充

- **样式**：全部沿用既有，任务组、子任务不加标签或符号。原型里的**红色虚线框＝本期新增的数据**（任务组、额满），只是标示给开发看，正式画面不显示框。
- 页签：任务设置、任务完成记录、任务报表统计有调整（画面标橘色「有调整」）；资料审核、黑名单设置不变。
- 任务名称（＋国际化）、适用端口、审核方式、排序、任务状态、操作：照既有。
- 分页：按任务算，任务组整组（母行＋明细行）算 1 笔，明细不拆到下一页（同报表 2.9）。
- 资料审核：页面照既有不变；任务组选人工审核时，子任务会进到这一页，任务ID 显示子任务 ID（1030-1）、任务名称显示子任务名称（同 2.8）。

### 2.8 后台 · 任务完成记录

一行＝一位会员的一笔奖励。

#### 规则

- **栏位**：照既有，不新增栏位。
- **任务名称**：基础任务照既有。子任务＝子任务名称；额外奖励没有名称，显示「额外奖励 · 任意完成 n 个」。属于哪个任务组看任务ID 就知道（1030-1、1030 都是 1030 这一组）。
- **子任务**：ID＝子任务 ID（1030-1）；例：充值满 ₱100。
- **额外奖励**：ID＝母 ID（1030）；例：额外奖励 · 任意完成 1 个。额外奖励不用审核，状态只会是自动发放、待领取、已领取，不会有待审核、审核未通过。
- **券类奖励**：奖励类型下方显示券名称（券管理后台的名称，如 ON色碟）；奖励值固定「1 张」（每次发 1 张，2.2）。
- **额满（新增状态）**：任务完成了，但名额满了领不到。自动发放＝完成时名额已经满了；用户手动领取＝还没领名额就满了（原本「待领取」改成「额满」）。状态红字，奖励值「—」。发放状态筛选多「额满」这个选项。
- **任务ID 搜索（新增）**：母 ID（1030）＝整组（子任务＋额外奖励）；子任务 ID（1030-2）＝只列该子任务；比对要完全相同（搜 103 不会出现 1030）。

#### 补充

- 其他状态照既有：待审核、待领取、自动发放、已领取、审核未通过，都是一般文字，只有「额满」红字。**没有「已过期」状态**。

### 2.9 后台 · 任务报表统计

看每个任务在所选时间（UTC+8）内**被完成几次**、**发出去多少奖励**。

#### 规则

- **累计完成次数**＝任务被**完成**几次，不管奖励领了没有。
- **累计发放**＝会员**真的拿到手**多少奖励，还没领的不算。积分、彩金加总数值；免费旋转、免费投注、优惠券、golden draw券加总张数（这 4 栏是新增）；券类**只算张数，不算价值**（价值只给前台显示，2.2）；没有这种奖励显示「—」。
- **任务组**：一行汇总＋下方明细，明细一律展开，不做收合。
  - 汇总行：ID＝母 ID（1030），名称＝任务组名称（不加标签）。完成次数**只加子任务**（额外奖励是完成子任务顺便送的，不是另外完成的任务）；发放**子任务＋额外奖励都加**（都是发出去的奖励）。
  - 子任务行：ID＝子任务 ID（1030-1），名称＝子任务名称（灰字缩排，不加符号）。
  - 额外奖励行：每档一行，ID＝母 ID（同 2.8），名称＝「额外奖励 · 任意完成 n 个」（灰字缩排）；完成次数＝达成这一档的次数。
- **小计、总计**：只加每个任务**最上面那一行**（基础任务行、任务组汇总行）；明细行不加，因为汇总行已经包含它们，再加会算两次。小计＝本页，总计＝全部查询结果。

#### 例子

任务组 1050（每日）：子任务 1 送积分 100、子任务 2 送积分 150、子任务 3 送积分 200；额外奖励「任意完成 2 个」送彩金 100、「任意完成 3 个」送积分 300。<br>小明今天完成子任务 1、子任务 2，同时达成「任意完成 2 个」，奖励都自动发放。报表这样加：

| 行 | 累计完成次数 | 累计发放积分 | 累计发放彩金 |
|---|---|---|---|
| 子任务 1 | ＋1 | ＋100 | — |
| 子任务 2 | ＋1 | ＋150 | — |
| 额外奖励 · 任意完成 2 个 | ＋1 | — | ＋100 |
| **任务组 1050（汇总行）** | **＋2**<br>（只加子任务） | **＋250**<br>（100＋150） | **＋100**<br>（额外奖励） |

如果是「用户手动领取」、小明还没领：完成次数照样 ＋1，发放先不加；等他领了，算在领的那天。

#### 补充

- **同一个人算几次**：每一期可以各算 1 次（连续 3 天完成每日任务＝3 次）；永久、限时只有一期，最多 1 次。
- **额满**：完成了但没领到奖励 → 完成次数要算，发放不算。
- **人工审核**：审核通过才算完成；待审核、审核未通过都不算。
- **算在哪一天**：完成次数看完成时间（人工审核看审核通过时间）；发放看会员拿到的时间（自动发放＝完成时间；奖励找回补领＝补领那天）。
- 搜索：币别、时间区间、任务名关键字照既有；任务组用任务组名称比对，搜到整组列出。
- **任务ID 搜索（新增）**：同完成记录（2.8）。母 ID（1030）＝汇总行＋全部明细；子任务 ID（1030-2）＝只列该子任务一行，小计、总计就是这一行的数字（这时画面上没有汇总行）。
- 分页：按任务算，任务组整组算 1 笔，明细不拆到下一页。
- 导出：内容同画面，含任务组明细行。

## 3 前台：会看到什么

### 3.1 前台 · 任务列表页签

页签按后台「任务时间」分类。

| 页签 | 显示 | 下方红字 |
|---|---|---|
| 全部(n) | 看得到的全部任务；n＝任务数，任务组整组算 1 | 不显示 |
| 基础任务 | 永久 | *任务完成后不会重置 |
| 每日 | 每日 | *任务将于每日12:00 AM重置 |
| 每周 | 每周 | *任务将于每周一12:00 AM重置 |
| 限时 | 限时、周限时 | *任务于活动期间内有效，结束后不会重置 |

#### 规则

- **页签分类**：只看任务时间，不看任务类别。例：永久的任务组在「基础任务」页签。
- **红点**：页签右上红色数字＝该页签所有可领取的数量（0 就不显示），**基础任务、子任务、额外奖励都要算**（每个「领取」按钮、每个可领宝箱各算 1）；未登录不显示（黑名单照既有）；领取后立即减少；**不含奖励找回**（找回看入口数字，3.8）。
- **卡片顺序**：由后端排好，前台照着显示：
  - 后台排序**越小越前面**，任务组卡和基础任务卡一起排（2.6）。
  - **已完成、额满**的排到最下方（任务组＝子任务、宝箱全部完成或额满）；任务时间结束前都留在列表上，倒数照常显示。
  - 刚领取完不马上重排，卡片留在原位；下次进页面才移到最下方。

#### 交互一览

| 操作 | 结果 |
|---|---|
| 进入页面 | 预设选「全部」；卡片照上方顺序；红色数字＝当下可领数。 |
| 点页签 | 只显示该页签的任务，下方换成对应红字（「全部」不显示红字）；不重新排序。 |
| 领取一笔（按钮或宝箱） | 「全部」和所属页签的红色数字都 −1，到 0 隐藏。 |

### 3.2 前台 · 基础任务卡

左边任务资讯，右边倒数和一个按钮。

#### 规则

- **标题**：一行，超出以「…」截断（各处文字长度见下方「前台文案长度一览」）。
- **进度**：资金类＝进度条＋「₱已达成 / ₱目标」；其他条件＝「进度 0 / 1」。
- **奖励标签**：图示＋内容，写法见下方「奖励怎么显示」。
- **已发送人数**：「已发送 x/y 人」（A128），有设名额才显示。
  - x＝实际领到奖励的人数（任务中心领取、自动发放都算）；y＝名额上限。
  - x 到 y（名额满）→ 整串红字；已经领到的会员看到的也是红字。
  - 永久任务不能设名额（2.4），所以不显示。左侧示例卡没设名额，看「中额·每日投注任务」。
- **倒数**：按钮上方红字，例「⏱ 6d 13:05:11」；永久任务不显示。
- **按钮**：照既有逻辑；名额满显示「额满」（3.5）。
- **任务简介**：标题后面的 ⓘ，照既有（3.10）。

#### 前台文案长度一览

| 文字 | 位置 | 显示几行 | 超出怎么处理 |
|---|---|---|---|
| 任务名称（基础任务、任务组） | 3.2、3.3 | 1 行 | 「…」截断；有 ⓘ 时 ⓘ 固定在名称后面，不会被挤掉 |
| 子任务名称 | 3.3 | 1 行 | 「…」截断 |
| 页签 | 3.1 | 1 行，不换行 | 固定文案；放不下时可左右滑 |
| 奖励标签、宝箱下方奖励 | 3.2、3.4 | 1 行，不换行 | 不截断；宝箱下方数字最多 6 位（2.2）；奖励标签不限位数 |
| 已发送 x/y 人、倒数、宝箱「n 个」 | 3.2、3.4 | 1 行，不换行 | 格式固定，不截断 |
| 领取成功弹窗：红字 | 3.6 | 1 行 | 不截断 |
| 领取成功弹窗：灰字券名称 | 3.6 | 1～2 行 | 超过 2 行用「…」截断 |
| 提示弹窗文案 | 3.9 | 自动换行，不限行数 | 不截断；任务名称长时弹窗跟着变高 |
| 奖励找回：任务名称 | 3.8 | 自动换行，不限行数 | 不截断 |
| 奖励找回：剩余可领时间 | 3.8 | 1 行，不换行 | 格式固定 |
| 任务介绍弹窗内容 | 3.10 | 自动换行 | 照既有 |

#### 奖励怎么显示（各处对照）

同一笔奖励在不同地方写法不一样，**以这张表为准**。例：彩金或积分 100、免费旋转价值 20、golden draw券 1 张。

| 位置 | 彩金／积分 | 免费旋转／免费投注／优惠券 | golden draw券 |
|---|---|---|---|
| 任务卡奖励标签（3.2、3.3）<br>额外奖励宝箱下方（3.4）<br>奖励找回清单（3.8） | 图示＋100 | 图示＋₱20 | 图示＋×1 |

- ₱价值＝后台奖励的「价值」栏（2.2）；golden draw券＝张数。
- **只有领取成功弹窗带券名称**：券管理后台的券名称（如 ON色碟），原样显示、不翻译；其他地方都不放。
- 图示依奖励类型，各处同一套。

### 3.3 前台 · 任务组卡

一张卡＝一个任务组：上方标题、进度、额外奖励，下方子任务。

#### 规则

- **倒数**：右上（永久不显示）。不放「任务组」角标。
- **任务简介**：ⓘ 放在任务组标题后面，子任务没有，照既有（3.10）。
- **进度**：「已完成子任务数 / 子任务总数」，达成就算（含还没领的）。人工审核：点「领取」送审（处理中），审核通过才算进度。
- **子任务行**：标题＝后台配置的子任务名称（2.3），一行超出以「…」截断；其余同基础任务卡，每行一个按钮。
- **收合**：预设显示**额外奖励＋1 个子任务**（照下方顺序排第一的）。**B 站 PC 版例外：预设 2 个**。其余点「查看全部 n ⌄」展开（n＝子任务总数），「收起 ⌃」收回；每张卡各自展开。子任务不超过预设数量时，不显示按钮。
- **子任务顺序**： 进度＝已达成 ÷ 目标（例：₱120 / ₱300＝40%）；处理中、未通过算 100%。同进度照后台顺序。领取后不马上重排，下次进页面才重排。
  1. **可领取**：放最前面。
  2. **进行中**：进度越快越前面。都还没开始＝照后台顺序，所以预设显示子任务一。
  3. **已完成、额满**：放最后面。

#### 补充

- 游戏分类页的「Task」区块不显示任务组（任务组不适用「游戏页展示」，2.1）。

### 3.4 前台 · 额外奖励

任务组卡上方的浅黄区块，一档一个宝箱，最多 3 个。档数、n、奖励照后台额外奖励设定（2.3）。

| 宝箱 | 样子 | 点了 |
|---|---|---|
| 未达成 | 灰蓝圆底＋银色宝箱 | 不能点 |
| 可领取<br>（只有手动领取） | 橘色圆底＋红色宝箱＋发光；宝箱开合，提示可以领取 | 领取 → 成功弹窗（3.6）→ 打勾 |
| 已领取 | 绿色圆底＋白色打勾 | 不能点 |

#### 规则

- **宝箱下方**：「n 个」＋奖励内容（图示＋红字，写法见 3.2 对照表）；进度条橘色走到目前完成数，还没到的是灰色。
- **审核**：额外奖励不用审核，宝箱不会出现处理中、未通过。
- **领取**：照后台「奖励发放方式」（2.6）。自动发放＝达成直接入帐，宝箱直接打勾；用户手动领取＝宝箱开合，点了才领。
- **限制**：不受名额限制，子任务完成就算 1 个，额满（没领到）也算；不进奖励找回，要在本期结束前领。
- **未登录**：见 3.7；黑名单照既有。

#### 交互一览（依奖励发放方式）

| 时机 | 用户手动领取 | 自动发放 |
|---|---|---|
| 完成数＜n | 未达成：灰蓝圆底＋银宝箱，**没有动画**，不能点 |  |
| 完成数达到 n | 可领取：橘色圆底＋红宝箱＋发光，**宝箱开合**；页签红色数字 +1 | **直接打勾**（绿色圆底＋白勾），**没有可领取状态、没有动画**；不跳领取成功弹窗（由提示弹窗 3.9 通知）；红色数字不变 |
| 点宝箱 | 跳领取成功弹窗（3.6）→ 打勾、停止开合；红色数字 −1 | 不能点 |
| 已领取 | 绿色圆底＋白勾，没有动画，不能点 |  |
| 本期结束还没领 | 领不到（不进奖励找回） | — |

### 3.5 前台 · 按钮与额满

**按钮的显示判断、点击行为、引导跳转全部照既有《任务按钮显示规则 v1.1》。**只多一处：「额满」（本节）。

#### 规则（额满）

- **何时显示**：奖励名额已满（后台名额上限，2.4），且这位会员本期还没拿到这项奖励；已拿到的照既有逻辑。
- **优先顺序**：额满会取代「还没完成」时的按钮（去完成、去充值等）和「领取」按钮（完成了还没领，名额就满了）；处理中、未通过照 v1.1 显示。人工审核的任务（2.6）：审核通过时名额已满 → 按钮显示额满，领不到。
- **样式**：不可点；淡灰玫瑰底、白字（日间 `#e2b4b4`、夜间 `#8a6464`）。
- **同时**：「已发送 x/y 人」变红字。名额就是按领取人数算，x 到 y 就额满。
- **适用**：基础任务、子任务；到了下一期名额重新计算，按钮恢复正常。

#### 点「领取」之后（基础任务、子任务）

| 情况 | 马上发生 | 按钮变成 |
|---|---|---|
| 不需审核 | 跳领取成功弹窗（3.6）；页签红色数字 −1 | 已完成（不可点） |
| 需人工审核 | 照既有（v1.1） | 处理中 |
| 名额满了 | 领不到 | 额满（不可点） |

- 领完卡片**不移位置**；下次进页面才排到最下方（3.1）。子任务同理（3.3）。

#### 补充

- **「领取任务」「已过期」**：v1.1 里有，但目前没有这两个状态，**前台不会出现，不用做**。
- **审核未通过**：显示「未通过」（照 v1.1）。

#### 红字写法

| 奖励类型 | 红字 |

| 免费旋转／免费投注／优惠券 | ₱价值，例：₱20；下方灰色小字放后台券名称，例：ON色碟 |
| golden draw券 | ×张数，例：×1 |

#### 交互一览（什么时候跳）

| 情况 | 跳不跳 | 说明 |
|---|---|---|
| 基础任务、子任务点「领取」（不需审核） | 跳 | 内容依这笔奖励类型（上表） |

### 3.8 前台 · 奖励找回

任务重置或结束后，还在「奖励领取时限」内没领的奖励，在这一页补领。

#### 规则

- **入口**：任务列表标题下方「奖励找回 ›」，红色数字＝可找回笔数。
- **清单**：一行一笔：任务名称（自动换行，不截断）、奖励（写法见 3.2 对照表）、剩余可领时间（不换行）。只有基础任务、子任务（名称「任务组名称 · 子任务名称」），没有额外奖励。
- **底部**：**不显示合计**（奖励类型可能混合），只放「一键领取」。
- **一键领取**：全部领取 → 弹窗：**通用奖励图示＋「奖励领取成功」**，不列奖励内容。之后清单清空、入口数字隐藏。
- **没有可找回**（清单为空）：入口还在、不显示数字；页内显示「暂无可找回的奖励」，「一键领取」反灰。

#### 交互一览

| 操作 | 结果 |
|---|---|
| 点「奖励找回 ›」 | 进入奖励找回页（H5 整页；PC 盖住右边内容区）：上方「‹ 奖励找回」→ 红字说明（照既有）→ 清单 → 底部「一键领取」。 |
| 点「‹」 | 回任务列表。 |
| 点「一键领取」 | 全部领取 → 弹窗（通用图示＋「奖励领取成功」）→ 点「确定」关闭 → 清单清空、显示「暂无可找回的奖励」、按钮反灰、入口数字隐藏。 |
| 剩余可领时间到 | 照既有（过期未领的奖励消失）。 |

#### 补充

- 有设名额的任务不进奖励找回（2.4）。
- 未登录：不显示入口。黑名单照既有。

### 3.9 前台 · 提示弹窗

会员完成任务时跳出弹窗提醒（H5 在底部导航列上方；PC 在内容区右下）。这是既有功能，只改两件事，其余照既有。有没有「领取」钮照后台「奖励发放方式」（2.6）。

> **只改两件事**
> 1. **图示、奖励依类型显示**：原本只有积分、彩金有图示，免费投注显示「Free Bet」、借用积分图示；改为每种奖励用自己的图示。<br>2. **左上关闭钮换样式**：灰蓝实心圆（#a7b0c9）＋白色 ✕，看下方示意；点了关闭，行为照既有。<br>**提示弹窗出现行为，不调整。**

#### 示意

> 示意图见 spec.html（这一节的画面示意）。

#### 规则

- **文案**：固定「奖励 {{a}}，恭喜完成 {{b}} 任务！」（A134）。
  - {{a}}＝这笔奖励：彩金／积分＝数值，券类＝₱价值（**不放券名称**，看图示），golden draw券＝×张数。例：100、₱20、×1（对照见 3.2）。
  - {{b}}＝任务名称；子任务、额外奖励一律用任务组名称。
  - 任务名称结尾已是「任务」，后面不再接「任务」，例：恭喜完成每日三连 · 组任务！这条只用于中文；其他语言照 A134 原样代入。
- **图示、关闭钮**：见上方「只改两件事」；图示放最左边，同任务卡（3.2）；关闭钮手动领取、自动发放都有。
- **长度**：文案自动换行、不限行数、不截断；任务名称长时弹窗跟着变高（见 3.2 文案长度一览）。

#### 交互一览（什么时候跳、怎么关）

| 情况／操作 | 结果 |
|---|---|
| 检查时机 | 登录进站约 2 秒后开始，每 10 秒检查一次新完成的任务；分页在背景时暂停 |
| 完成一笔（基础任务、子任务、额外奖励每档） | 跳一次；同一笔只跳一次。跳过的纪录存在会员这台装置的浏览器，登出再登录会清掉，系统若仍列为新完成会再跳一次 |
| 用户手动领取 | 右边有「领取」 |
| 自动发放 | 没有按钮（奖励已入帐） |
| 同时完成多笔 | 一次只显示一个，每 10 秒跳下一个 |
| 正在任务中心页面 | 不跳，之后也不补跳 |
| 未登录 | 不跳（黑名单照既有） |
| 其他页面（含游戏页、活动页） | 都跳；下载页、404、维护页、App 内嵌不跳 |
| 不动 | 3 秒自动关闭 |
| 点左上关闭钮 | 只关这一个；下一笔照 10 秒节奏再跳 |
| 点「领取」 | 弹窗关闭并直接跳转，不另跳确认：H5 到奖励中心（/reward-center）、PC 到任务中心（/user/task-center）；之后人在任务中心就不再跳 |

### 3.10 前台 · 任务简介

任务标题后面的 ⓘ，点了看任务简介。这是既有功能，本期不改。

#### 规则（照既有）

- **显示**：后台「是否显示任务简介」选「是」才显示 ⓘ；选「否」不显示（2.1）。
- **位置**：基础任务在标题后面；任务组在任务组标题后面，子任务没有。
- **弹窗**：点 ⓘ 跳「任务介绍」弹窗，内容＝后台「任务简介」，自动换行（照既有）；点「确定」或 × 关闭。

## 4 多语言文案

任务中心前台文案共 5 种语言：中文（zh）、英文（en）、菲律宾语（ph）、越南语（vi）、宿雾语（ceb）。

#### 规则

- **以运营的翻译文件为准**：本期全部新增，A123～A134。
