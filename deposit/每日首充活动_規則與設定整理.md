## 一、活動內容規則

### 1. 資格判定（充值成功回呼觸發，自動判定）

| 項目 | 規則 |
|---|---|
| 觸發點 | 充值成功回呼 `DailyRechargeActivityServiceImpl.rechSuccess(UserRech)` |
| 參加意願 | 玩家下單時須勾選「參加活動」(`participateActivity == 1`) |
| 活動選擇 | 訂單帶 `dailyRechargeId` 指定活動；未帶時相容舊版固定取 id=1 |
| 首充定義 | 當日（GMT+8）第一筆已支付訂單（`paidCount == 0`） |
| 一日一次 | Redis `SETNX` key `daily_recharge_activity.{userId}.{yyyyMMdd}`，TTL 1 天 |
| 參與條件 | 目前只開放「同 IP 每日可申領帳號數上限」(`ipAccount`) |
| 排除對象 | 外部投注站來源用戶（`EXTERNAL_STATION` / `ONLINE_EXTERNAL_STATION`）不發獎 |
| 最低金額 | 充值金額低於該渠道 `minimumMoney` 不發 |

### 2. 獎勵計算

- **三條渠道獨立配置**：平台自有 `rechargeConfig`、GLife/OKFUN `otherRechargeConfig`、Maya `mayaRechargeConfig`，依用戶註冊來源選用。
- **VIP 分級**：每渠道依 VIP 等級取一列配置；VIP 未命中退回一般會員 (PT) 配置。
- **獎勵類型 `rewardType`**：`0` 彩金、`1` 積分、`2` 免費旋轉。

| 類型 | 計算 / 發放 | 流水 |
|---|---|---|
| 彩金 | `充值金額 × percent / 100`，超過 `limit` 取 `limit`，小數第 2 位無條件捨去，結果為 0 不發 | 計流水 |
| 積分 | `pointsService.adjustUserPoints`，交易類型 `RECHARGE_REWARD` | 不計流水 |
| 免費旋轉 | 依 `freeSpinConfigId` 發券，取得方式 `DEPOSIT` | 不計流水 |

- **彩金稽核流水**：`checkAmount = (含獎金 ? 獎金 : 0) + (含本金 ? 本金 : 0)`，`validCheckPercentage = checkAmount × flowRatio / rewardAmount × 100`。
- 流水倍數 `flowRatio`、含本金 `principal`、含獎金 `rewards` **整個活動共用一份，不分天數區間**。

### 3. 天數區間（D1～Dn 分段獎勵，OKF-2147 改造）

- 活動可切多個天數區塊（表 `daily_recharge_activity_day_config`），每區塊各有一套「三渠道 × VIP」獎勵矩陣。
- **校驗**：
  1. 區塊依 `dayStart` 排序後須連續、不重疊、無缺口
  2. 最後一塊 `dayEnd` 必須等於活動自然天數（GMT+8 日曆日差 +1）
  3. 不符合丟 `DAILY_RECHARGE_DAY_RANGE_CONFIG_REQUIRED` / `DAILY_RECHARGE_DAY_RANGE_INVALID`
- **今日區塊**：以活動開始時間到現在的自然天數落在哪個 `[dayStart, dayEnd]` 決定。
- **版本防錯**：玩家提交充值時帶 `configVersion`（區塊 id），跨天配置錯位回 `DAILY_RECHARGE_ACTIVITY_UPDATED`；獎勵記錄 `day_range` 記錄實際套用區塊。
- 無區塊的舊活動退回舊版整表 `vip_config`。

### 4. 狀態與展示

| 項目 | 規則 |
|---|---|
| 狀態 | `1` 開啟 / `2` 關閉，無草稿 |
| 前台展示 | 狀態開啟 **且** 落在「顯示時間」；顯示時間為空則看「活動時間」 |
| 領取 / 發放 | 表單目前只可選「自動」，實務為自動判定 + 自動發放 |
| 多活動 | 可並行進行，前台 v4 介面回傳全部進行中活動 |
| 時區 | 統一 GMT+8 (`Asia/Shanghai`) |

## 二、後台設置邏輯

**頁面**：`DailyRechargeActivityIndex.vue`，含「活動列表」與「獎勵記錄」兩個分頁。

| 活動時間 | `start_time` / `end_time` | 必填（23105） |

### 2. 保存邏輯

- 新增：`id` 為 0 / 空 → 建新記錄；編輯：取原記錄覆蓋欄位。
- 天數區塊整批先 `deleteByActivityId` 再依提交順序重插。
- 圖片依 `id` 是否存在決定 update / save。
- 事務提交後透過 `cacheNotifyService` 清快取。
- 免費旋轉類型必須帶 `freeSpinConfigId`。

### 3. 列表頁

- 欄位：活動編號、活動名稱、活動時間、顯示時間、建立時間、建立人、狀態。
- 操作：編輯（權限 `10140501`）、查看記錄（權限 `10140502`）。

### 4. 獎勵記錄頁

- 欄位：活動 ID、活動名稱、會員帳號、充值訂單號、充值金額、申請時間、獎勵內容、備註。
- 備註可追加，單次 ≤ 2000 字；支援匯出（先 prepare 判斷是否異步）。

## 六、現有測試活動（測試環境 spplat1）

> 來源：測試環境公開介面 `GET https://api-okbet-v1.cxsport.net/api/front/promotions`（未登入即可取得），查詢時間 2026-09-11。
> 未登入只能看到「平台自有通路 × 一般會員(PT)」那一列的百分比與流水倍數；各 VIP 等級、其他通路、Maya 通路、上限與最低金額須登入後台 `活動列表 → 編輯` 查看。

| 欄位 | 活動 id 4 | 活動 id 5 |
|---|---|---|
| 活動名稱 (`titleText`) | 每日小首充1 | 每日首充活动-长时间111 |
| 副標題 (`subTitleText`) | 每日小首充 | 内容标题文字 |
| 活動牆代碼 (`code`) | `daily_first_deposit_4` | `daily_first_deposit_5` |
| 活動時間 | 2026-09-08 00:00 ～ 2026-09-30 23:59:59 | 2026-09-01 00:00 ～ 2026-09-30 23:59:59 |
| 自然天數（決定天數區塊總長） | 23 天 | 30 天 |
| 首頁顯示 (`frontPageShow`) | 1 顯示 | 0 不顯示 |
| 獎勵百分比 (`amount` = `percent`，PT/平台通路) | 23% | 10.18% |
| 流水倍數 (`multiple` = `flowRatio`) | 3 倍 | 4 倍 |
| 活動類型 (`activityType`) | 4 | 4 |
| 活動內容 (`contentText`) | `<p>sfasdfaf</p>` | `<p>活动内容</p>` |
| 圖片 | titleImage / indexImage / contentImage / popImage 四張皆已上傳 | 同左 |
| `isActive` | false（未登入固定 false） | false（未登入固定 false） |

**解讀**
- 兩個活動皆狀態開啟且在顯示時間內，所以會出現在活動牆；`isActive` 在未登入時一律 false，登入後才依「今日是否已首充」判斷。
- id 4 的 `frontPageShow=1`，表示會出現在首頁活動入口；id 5 只在優惠活動牆顯示。
- `amount` 是未登入時取的預設列（平台通路、PT 等級）；同一活動的 VIP 高等級可能是不同百分比。
- 兩者活動時間皆到 9/30，因此後台的天數區塊最後一塊 `dayEnd` 必須分別等於 23 與 30，否則保存會被擋。

## 七、後台設定範例（完整 save 請求說明）

以下為一個「7 天活動、兩段天數區間、彩金型」的完整範例，對應後台 `POST /api/admin/dailyRechargeActivity/save` 的請求體與表單操作。

- 活動名稱：每日首充加碼（範例）
- 活動時間：2026-10-01 00:00:00 ～ 2026-10-07 23:59:59（自然天數 = 7）
- 顯示時間：2026-09-28 ～ 2026-10-07（提前 3 天曝光，期間玩家可看到但 10/1 前充值不發獎）

### 發獎試算（以上述範例）

| 情境 | 計算 | 結果 |
|---|---|---|
| 10/1（D1）PT 玩家、平台通路，充值 1,000 | 1000 × 20% = 200，未超上限 500 | 彩金 200；稽核流水 = (1000 + 200) × 3 = 3,600 |

| 10/3（D3）PT、平台通路，充值 80 | 80 < 最低 100 | 不發 |

### 常見保存失敗原因

| 錯誤 | 原因 |
|---|---|
| 23104 / 23105 | 活動名稱或活動時間未填 |
| 23106 | 沒有任何天數區塊 |
| 23107 / 23108 | 區塊缺 dayStart / dayEnd |
| `DAILY_RECHARGE_DAY_RANGE_INVALID` | 區塊不連續、重疊，或最後一塊 dayEnd ≠ 自然天數（例：活動 7 天卻只設到 D5） |
| 前端擋下 | 彩金 / 積分型缺 percent 或 limit；免旋型缺 freeSpinConfigId |
