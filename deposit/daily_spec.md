## 1 这活动在干嘛

### 懒人包 ▲（10/6 新增）

玩家每天存多笔，**每一笔都有奖金**；奖金按「**星期 × VIP 等级 × 第几笔 × 渠道**」配，一律发彩金。

**玩家怎么玩**
1. 首页 Deposit 有 BONUS 条 → 进存款页
2. 勾复存券、输入金额（达门槛），券面显示要打多少码
3. 送出＝用掉一次；钱入账才发奖
4. 券换下一笔；当天用完或不发奖日券不出现；00:00 重置

**后台要配（第 2 章）**
- 基本信息：活动时间不可重叠（2.2）
- 奖励：七天 × 11 级 × 每天 1～10 笔 × 3 渠道；可设不发奖日（2.3）
- 参与条件：活动流水倍数、同 IP 账号数（2.4）
- 内容：4 张图＋标题＋说明（2.5）
- 记录页：多 5 栏，查每笔怎么算（2.7）

**发奖关键规则（第 3 章）**
- 算哪天、第几笔、用哪份配置：都看**送出时间**（GMT+8）
- 用掉一次：勾券送出，充值失败也算
- 奖金＝金额 × %，超过上限取上限
- VIP：升级次日生效，降级次月 1 号生效（3.3）

**前台改哪里（第 4 章）**
- 4.1 首页：有券时 Deposit 上方加黄色 BONUS 条
- 4.2 存款页：小 banner、复存券（排序、打码金额）、金额区角标与试算
- 4.3 详情页：今日逐笔清单；不发奖日只剩基本资讯

### 这是一档独立的新活动

- 后台是**另一张独立页面**：专项活动 →「**每日存款活动**」，排在「每日首充活动」下方。
- 活动、配置、领奖记录、后台授权、前台的券，**全部和每日首充分开**。两档互不影响，可同时在跑。
- 后台怎么配，**照每日首充现有的做法**；但只是照做法，**不共用**同一份功能或数据。
- 测试要**两档分开验**：改本活动不可影响每日首充，反过来也一样。

标签意思：
- 【同每日首充】＝ 做法照每日首充，这里不重写细节；但仍是本活动自己的一份。内文写「同每日首充」也是这个意思。
- 【不同】＝ 参照每日首充，但本活动**改掉**的地方，以本规格书为准。
- 【新增】＝ 每日首充**没有**、本活动新做的。
- 前台章节专用（和每日首充无关）：【异动】＝ 前台现有页面**要改**；【同现况】＝ 前台现有元件**照旧**。

### 本文件用词

- 「**存款**」＝「**充值**」，同一件事。
- 「**用掉一次**」＝勾券并送出存款，**成功失败都算**。
- 「**领到奖**」＝钱入账成功、奖金发出。和「用掉一次」不同（见 3.1）。
- 「**奖励列表**」＝前台 `Rewards ＞ Promotion` 区的活动卡片列表（见 4.3.3）。
- 「**渠道**」＝平台／glife／maya 三种（见 2.3.7）。

### 概要

玩家一天存多笔，**每一笔都能拿奖金**，每一笔的奖金可以不一样。

| 项目 | 说明 |
|---|---|
| 奖金怎么算 | 存款金额 × 百分比，超过上限就取**上限**。 |
| 百分比看什么 | 看四件事：**今天星期几、VIP 等级、今天第几笔、渠道**。<br>后台配法：七天各一组 → 每组 11 个等级 → 每个等级一笔一列 → 每一笔分平台／glife／maya 三个渠道，各填％与上限。<br>▲ 每一天可以设成**不发奖**，例如只发一三五、或只发二四六（见 2.3.9）。 |
| 每天可领几笔 | 后台配 **1～10 笔**，每一天、每个等级可以不一样。 |
| 什么算用掉一次 | 勾券并送出充值就算，**充值失败也算**（见 3.1）。<br>没勾券、或没达门槛的存款，不算。 |
| 周期 | 照**日历的星期几**循环，不是照「活动第几天」。 |
| 发什么 | 一律发**彩金**，要计流水。不发积分、不发免费投注。 |
| 怎么参加 | 在存款页**自己勾选那张券**。 |
| 能同时开几档 | 档数不限，但本活动各档**时间不可重叠**（见 2.2.4）。<br>所以任何时间最多一档在跑、前台最多一张复存券。<br>其他活动（含每日首充）不受影响。 |

### 2.2.4 保存时会挡下

| 情况 | 失败提示文案 |
|---|---|
| 活动名称留空 | 活动名称不可为空 |
| 活动时间缺一格 | 活动时间不可为空（**缺哪一格标哪一格**） |
| 活动时间起 > 迄 | 活动时间的开始不可晚于结束 |
| 排序留空／负数／小数 | 排序不可为空，请填 0 以上的整数 |
| **活动时间重叠** | 活动时间与「{冲突活动的名称}」（活动编号 {编号}，{起}～{迄}）重叠，同一天只能有一个活动在跑，请改到不重叠的日期 |

#### 重叠怎么判

| 情况 | 结果 |
|---|---|
| 跟谁比 | 本列表里**开启中**的其他活动；编辑时不跟自己比。每日首充等其他活动不比。 |
| 怎么比 | **只比日期**，不看几点几分：只要有**一天重复就挡**。 |
| A 到 9/30，B 从 9/30 起 | **挡**（就算 A 当天 10:00 结束、B 15:00 才开始） |
| A 到 9/30，B 从 10/1 起 | 放行 |
| 存成「关闭」 | 不检查 |
| 从关闭改开启再保存 | **要检查** |
| 活动时间还没填好 | 不检查这一条 |

挡的是**时间重叠**，不是「已经有活动开着」。时间错开，就可以同时开启多档。

版型同每日首充，只多了一层**星期**：七天 × 11 个 VIP 等级，每个等级一笔一列。

### 2.3.1 画面结构（三层）

| 层 | 说明 |

### 2.3.2 每日可领笔数

每个等级区块上方一个输入框，**填几就出现几列**。

| 项目 | 说明 |
|---|---|
| 能填什么 | **1～10 的正整数**。不能填 0、负数、小数。<br>· 超出范围 → 拉回边界（0→1、12→10）。<br>· 清空后离开输入框 → 回到清空前的数字。 |

| 初值 | 新增活动时，七天 × 11 级都是 **3 笔**，每一格都是空的（三个字段必填，见 2.3.8）。 |

### 2.3.4 复制与套用

两颗钮的来源**都只有 VIP0**。

| 功能 | 位置 | 行为 |
|---|---|---|
| **复制这天到其他天…** | 星期页签下方操作列 | 把**这一天的 VIP0** 复制到勾选的天。<br>· 目标天：套用中的等级跟著变；已取消套用的不动。<br>· 面板：不列来源那天；可多选；没选时主按钮不可点；选了显示「复制到 N 天」；换星期自动收起。<br>· 完成后：目标页签反蓝打勾约 5 秒；绿色提示「已把周一的 VIP0 配置复制到 2 天：周六、周日（含每日可领笔数）」。 |

| 层 | 说明 |

### 2.3.6 活动期间轮不到的星期

| 项目 | 说明 |

## 3 发奖逻辑（判断逻辑表）

一笔存款进来，系统怎么算要发多少。

> **四个条件定出一格**
> **① 今天星期几** → **② 玩家 VIP 等级** → **③ 今天第几笔** → **④ 玩家所属渠道**。
> 这四个定了，就找到一格。这一格的**最低存款金额（三渠道共用）、奖励％、上限金额**，就是这一笔的规则。

### 3.1 笔序与「当日」 【核心规则】

| 项目 | 说明 |
|---|---|
| 第几笔 | ＝今天**已用掉的次数 ＋ 1**。<br>这个数字决定两件事：套哪一列、今天还能不能再领。 |
| 怎样算用掉一次 | 勾了券、送出充值，就算用掉一次。**充值成功或失败都算。**<br>没勾券的存款：不算次数、也不发奖。 |
| 什么时候发奖 | 钱**入账成功**才发。<br>以下情况会「用掉一次，但没领到奖」：充值失败、同 IP 超限（见 2.4）、外部投注站来源用户（会员本来就有的属性，后台不配置）。 |
| 算哪一天 | 看**送出充值的时间**，不看入账时间。时区 **GMT+8**，00:00 换日。<br>例：23:59 送出、00:01 入账 → 算 23:59 那一天。充值失败的，也算送出那天。<br>第几笔、用哪个星期、在不在活动时间内、▲ 用哪份配置，**都看这个时间**。 |
| 用哪一组 | 看那一天**日历上的星期几**，不是「活动第几天」。<br>活动不满一整周时，轮不到的星期就不会发生（后台已提醒，见 2.3.6）。<br>▲ 那一天如果设成**不发奖**（见 2.3.9）：前台没有券可勾，不发奖、不算次数。 |
| 过了 00:00 | 第几笔重新从 1 算；换成新一天的星期；昨天升上去的等级开始生效。<br>降级不在这时候换（见 3.3）。 |

### 3.2 门槛与奖励计算

| 项目 | 说明 |
|---|---|

### ▲ 4.2.5 （10/2 异动、10/6 调整）券 · 数字从哪来 【券面改显示打码金额】

券面显示的是这位玩家**下一笔**的数字，取后台这一格：
**今天星期几 × VIP 等级 × 渠道 × 第（今天已用次数 ＋ 1）笔**
VIP 等级取现在生效的那一级（见 3.3）。

| 券面上的 | 取后台哪一栏 |
|---|---|
| 百分比 | 奖励配置 → 玩家**所属渠道**那一栏（平台／glife／maya）的「每日复存奖励」。 |
| `Capped At` | **上限金额**（一样取所属渠道那一栏） |
| `Min Deposit` | **最低存款金额**（三个渠道共用）；也是金额区「低于下限」的门槛（见 4.2.6） |
| ▲ `Conditions:`<br>`Complete ₱X Bets To Withdraw` | 直接显示**系统算好的打码金额**（算法见下表），取代原本的 `Turnover: 3x turnover of deposited and bonus`。文案照设计稿。 |
| `Re-deposit Coupon`、`TOU` | **后台不配**：券名前台写死；TOU 是现有共用元件。 |

券面文案太长用「…」截断；**百分比和 `Capped At` 不能被挤掉**。

#### ▲ 打码金额 X 怎么算（10/6 调整）

| 项目 | 说明 |
|---|---|
| 公式 | **X ＝ 充值流水 ＋ 活动流水**<br><br>**① 充值流水 ＝ 充值金额 × 会员层级稽核比例 × VIP 稽核比例**<br>· 会员层级比例：用**现有会员层级配置**，本活动不配。<br>· VIP 比例：用**现有 VIP 配置**，和层级比例**相乘**。<br>　例：层级 80%、VIP1 50% → 80% × 50% ＝ **40%**。<br>· **VIP 流水设成不计算 → 不乘 VIP 比例**，只用层级比例。<br><br>**② 活动流水 ＝（勾选的本金 ＋ 勾选的奖金）× 活动流水倍数**<br>· 勾哪些、几倍：看本活动「奖金所需流水」（见 2.4）。2.4 留空 → 这一段是 0，只算 ①。<br>· 本金＝充值金额；奖金＝这笔充值算出的奖金（见 3.2，有上限）。 |
| 充值金额用哪个 | 用 Payment Amount **现在输入的金额**，即时算，不用按 Submit。<br>· **没勾券 → 显示 `₱0`**（这笔不带券、不发奖，不用打活动的码）（10/6 调整）<br>· 还没输入 → 显示 `₱0`<br>· 低于这一笔的 `Min Deposit` → 显示 `₱0`<br>· 达到门槛 → 开始算 |
| 换下一笔时 | 百分比、上限、门槛变了，**X 跟著重算**。 |
| 金额格式 | 计算时留 2 位小数，第 3 位起直接舍去；显示跟券面其他金额一样（整数不补 .00）。 |

#### ▲ 例子（10/6 调整）

设定：这一笔 **20%**、上限 2,000、门槛 500；充值流水比例 **40%**（层级 80% × VIP 50%）；活动流水 **3 倍**（勾本金＋奖金）。

| 步骤 | 怎么算 | 结果 |
|---|---|---|
| 奖金 | 1,000 × 20% | 200 |
| ① 充值流水 | 1,000 × 40% | 400 |
| ② 活动流水 | （1,000 ＋ 200）× 3 | 3,600 |
| **券面显示** | 400 ＋ 3,600 | **₱4,000** |

其他情况：没勾券、没输入、或低于门槛 500 → **₱0**；VIP 流水不计算 → ① 改成 1,000 × 80% ＝ 800 → **₱4,400**。奖金所需流水留空 → 只算 ① ＝ **₱400**。

### 4.3.2 未登入时

- 不知道玩家几级，**一律显示「平台渠道 × VIP10（最高级）」那一组**。
- `Bonus %`／`Max Bonus`：取这组今天**百分比最高的那一笔**，两格**用同一笔**（不另外找上限最高的）。百分比一样就取**比较前面**的那笔。百分比前面**加 `Up To`**（照现况）。
- 清单**照常列出**这组每一笔，但**都是一般样式**：不高亮、不变灰。
- 登入后 → 换成他自己等级的清单；两格改成**下一笔的确定值**，**不加 `Up To`**。
